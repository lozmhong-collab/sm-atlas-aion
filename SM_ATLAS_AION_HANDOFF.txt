TXT 작성일: 2026-10-10 / 최신 구현·검증일: 2026-10-10 / 제품 버전: 0.1.0

이번에 회사에서 이어서 할 일 — 먼저 읽기
컨플루언스 화면과 Electron MCP 커넥터는 집에서 1차 구현했다. 회사에서 UI를 처음부터 다시 만드는 요청이 아니다.
기존 회사 GitLab 작업에 이번 변경을 합친 후, 이미 사용하는 개인 mcp-atlassian 연결로 실제 조회·생성·수정을 검증한다.
회사에서 실제 응답 형식이 다르면 커넥터의 해당 부분을 보완한다. 회사 CA/프록시/개인 H-Chat CLI 설정과 기존 작업은 보존한다.
현재 상태는 "코드 구현 및 로컬 오프라인 MCP 검증 완료 / 실제 회사 MCP 및 모델 왕복은 현장 확인 필요"이다.
이 전달은 전체 소스 스냅샷 TXT이며, 설치 EXE나 회사의 최신 소스를 이미 병합한 결과가 아니다.
이전 공개 전달 f78abcf(2026-10-08)와 비교해 소스 60개 파일이 추가/변경됐고 삭제된 파일은 없다.
컨플 변경 외에도 이전 세션의 CLI 버전 info 안내 정리 변경이 함께 포함돼 있다. 기존 프로젝트/스킬/설치기 소스는 유지한다.

컨플루언스 구현 — 2026-10-10
- 프로젝트 폴더별로 기존 stdio MCP 서버와 루트 페이지 URL을 연결한다. 경로를 URL로 교체하지 않는다.
  workspace.confluence에 연결 정보만 저장한다. PAT·명령줄·본문을 프로젝트 설정에 복제하지 않는다.
- 프로젝트 화면의 "컨플 연결"에서 루트를 확인하고 저장한다. 세션 오른쪽 작업공간 패널의 "컨플루언스" 탭을 사용한다.
- 문서 트리는 펼치는 분기의 직접 하위 목록만 가져오고, 본문은 문서를 선택했을 때 조회한다.
  문서 전체를 로컬 폴더로 동기화하거나 모든 본문을 미리 수집하지 않는다.
- 검색은 루트 범위 CQL과 실제 상위 관계 확인을 함께 사용한다. 결과는 최대 50개이며 무제한 전체 검색은 아니다.
- 새 세션의 실제 첫 문의에 루트·출처 규칙과 직접 하위 문서 최대 25개를 전달한다.
  빈 세션 생성만으로 모델 요청을 하지 않는다. 기존 세션에는 선택한 문서를 현재 입력창으로 넣을 수 있다.
- "AI 초안 요청"은 현재 Claude/Codex 세션의 입력창에 요청을 넣는다. 사용자가 전송한다.
  "최근 AI 답변 가져오기"로 초안을 편집기에 넣고 확인한 뒤 "확인한 초안 게시"를 누른다.
- 하위 문서 생성과 특정 헤딩의 섹션 수정이 구현됐다. 전체 본문 교체·삭제·이동은 이번 UI에 없다.
  쓰기 성공은 서버에서 다시 읽어 확인하며 결과가 불확실한 경우 자동으로 중복 요청하지 않는다.
- 섹션 수정 전에 페이지 버전을 확인한다. 확인과 실제 수정 사이의 경쟁까지 서버가 원자적으로 막는지는 현장에서 확인한다.
- 앱의 루트 범위와 문맥 규칙은 별도로 실행되는 CLI MCP 도구의 ACL이 아니다. 개인 PAT와 서버 권한은 그대로 유지한다.
- 본문 뷰어/데모 서버는 메모리 기반이지만 참고자료를 입력창에 넣으면 저장된 초안이나 대화 이력에 남을 수 있다.
  24시간 자동 삭제, Teams 수집, 임베딩/벡터 RAG, 앱 차원의 개인 H-Chat 키 강제 로그인은 구현 완료로 표현하지 않는다.

회사에서 연결하는 순서
1. TXT를 새 폴더에 검증·복원하고 회사 최신 코드와 비교해 컨플 변경을 반영한다. 아래 파일 목록과 가이드를 참고한다.
2. 기존 회사 빌드 환경과 캐시를 사용해 타입·번역·관련 테스트와 앱 빌드를 확인한다. 필요 없이 Bun/런타임을 재설치하지 않는다.
3. 설정 → 도구에서 개인 uvx.exe → mcp-atlassian stdio MCP를 등록한다. PAT는 개인 설정에만 넣고 출력/공개 Git에 넣지 않는다.
4. 사진의 --no-confluence-ssl-verify / --no-jira-ssl-verify를 그대로 전달하지 않는다. 이 새 커넥터는 TLS 검증 비활성화를 거부한다.
   승인된 회사 CA로 Python/uv의 REQUESTS_CA_BUNDLE, SSL_CERT_FILE 및 필요 시 승인된 UV_NATIVE_TLS를 설정한다.
   기존 Electron 빌드의 NODE_EXTRA_CA_CERTS만으로 Python MCP의 인증서 신뢰가 구성된다고 가정하지 않는다.
5. 읽기 권한이 있는 루트 페이지 URL로 연결 → 트리 펼치기 → 본문 조회 → 검색 → 현재 세션 참고를 확인한다.
6. 실제 개인 H-Chat로 연결된 Claude/Codex에 참고자료를 보내 답변과 도구 사용을 확인한다. H-Chat 키와 컨플 PAT는 별개다.
7. 승인된 테스트 문서에서 AI 초안 요청 → 답변 가져오기 → 직접 확인 → 하위 생성/섹션 수정 → 재조회로 결과를 확인한다.
8. 회사의 실제 도구 이름·입력·응답, 페이지 ancestors/version 및 동시 수정 동작이 다르면 해당 adapter/codec만 보완한다.
   미리 모든 미확인 항목의 답을 기다리며 구현을 멈출 필요는 없다. 실제 실패/차이가 확인되는 지점부터 수정하고 결과를 보고한다.

회사 MCP 계약과 보완 지점
- stdio 자식 프로세스: uvx.exe에서 mcp-atlassian 실행. 개인 PAT 인증이며 H-Chat 인증이나 OAuth 연동으로 오해하지 않는다.
- 실제 tools/list 이름의 confluence_* 또는 mcp__atlassian__confluence_* 접미사를 지원한다. 중복/모호한 도구 이름은 거부한다.
- get_page, get_page_children(parent_id/start/limit), search(query/limit), create_page(parent_id), update_page_section 계약을 사용한다.
- FastMCP 텍스트 JSON/structuredContent, metadata/page 래퍼를 해석한다. 페이지 id/space/ancestors/version/content가 필요하다.
- 서버의 정확한 패키지 버전, 검색 추가 페이지, 큰 공간 트리, 원자적 버전 충돌 검사는 집에서 확인할 수 없다.
  이번 구현은 전체 공간 tree 도구에 의존하지 않고 get_page_children의 start/limit 페이지네이션으로 탐색한다.
- UI를 재작성하거나 Rust AionCore를 새로 작성할 필요는 없다. 등록된 서버 설정은 기존 백엔드에서 읽고 Electron main이 MCP와 통신한다.

이번 전달 내용
사용자가 요청한 기본 구조는 "프로젝트 경로 → 여러 독립 세션"이다.
팀 생성이 메인 흐름이 아니다. 팀·예약 작업·어시스턴트 관리는 필요할 때 펼치는 부가 기능이다.
이 TXT는 프로젝트 전체 소스와 파일 복원 도구를 포함한다. 실행 EXE를 TXT로 바꾼 파일은 아니다.
기존 프로젝트·세션 변경에 회사용 명칭·기본 스킬·MCP 안내와 Windows 설치기 개선을 추가했다.
기존 다운로드/복원 절차와 호환되도록 Git 저장소 및 TXT 파일 이름은 그대로 유지한다.

구현된 사용 흐름
1. 사이드바의 "프로젝트 추가"로 실제 작업 폴더를 등록한다.
2. 세션이 없는 폴더도 프로젝트 목록에 남는다. 목록과 마지막 선택 경로를 별도로 저장한다.
3. 프로젝트의 + 또는 상단 "새 세션"으로 해당 폴더에서 새 세션을 만든다.
4. 새 세션 화면에서 프로젝트와 사용할 Claude/Codex 등을 선택한다.
5. 빈 세션을 만들거나 첫 요청을 입력한다. 각 세션은 서로 다른 conversation ID와 독립 이력을 가진다.
6. 기존 세션을 선택해 전환하고, 선택한 프로젝트 경로에서 다음 세션을 시작한다.
7. 빈 프로젝트의 등록을 해제하면 선택 경로도 정리한다. 실제 폴더와 파일은 삭제하지 않는다.
8. 기존 사용자 지정 workspace의 세션도 프로젝트 아래에 모은다. 팀 소속 세션은 분리한다.

저장과 화면 구성
- 프로젝트 목록/선택: AionCore client settings의 workspace.projects.
- 데스크톱의 로컬 인증에는 web user 객체가 없으므로 현재 OS 사용자의 앱 데이터 프로필을 사용한다.
- 세션 생성은 기존 AionCore conversation API와 workspace/custom_workspace 계약을 사용한다.
- 첫 메시지에 따라 빈 세션의 기본 제목을 갱신한다.
- 프로젝트의 파일 패널과 미리보기 범위를 새 세션 작성 화면에서도 이어받는다.
- 새 문구는 한국어와 영어를 제공한다. 나머지 upstream 언어에는 해당 새 문구를 영어로 제공한다.
- 기존 SM Atlas 제품 정책과 회사 환경 진단 기능도 포함한다.

회사 기능 수정 — 2026-10-08
- 앱 화면, 번역, 알림, 설치 문구의 제품 이름을 SM Atlas로 정리했다.
  upstream 라이선스/저작권과 기존 저장 키·환경변수·백엔드 API 식별자는 호환성을 위해 유지한다.
- 회사 프로필의 소개 화면에서 원본 공개 서비스 링크와 소비자용 업데이트 설정을 숨겼다.
- resources/company-skills에 회사용 기본 스킬 12개를 따로 구성했다.
  자동 주입 6개: company-context, sm-atlas-config, skill-creator, cron, conversation-create, session-message.
  선택 6개: pdf, mermaid, officecli, officecli-docx, officecli-xlsx, officecli-pptx.
  원본 WebUI·메신저·SNS·채용·moltbook·openclaw 설치 스킬은 실제 기본 카탈로그와 주입에서 제외한다.
- 개발/패키지 실행 시 회사 스킬 경로를 백엔드에 지정한다. 필수 파일이 없으면 원본 스킬로 대체하지 않는다.
- 스킬은 지시문과 도구 사용 절차다. 문서·도식 도구의 별도 의존성 설치가 필요할 수 있다.
  목록에 있다는 이유만으로 회사 PC에서 모든 기능의 실제 실행이 확인된 것은 아니다.
- 앱 지원 agent 범위인 Claude/Codex로 스킬 화면의 비서 목록을 제한했다.

복원 방법
전체 TXT를 AI 대화에 한 번에 붙이지 말고, 먼저 이 안내와 복원 도구만 읽는다.
SM_ATLAS_AION_SOURCE.txt의 RESTORER_SCRIPT_BEGIN과 RESTORER_SCRIPT_END 사이를
restoreBundle.mjs로 저장한다. 마커 줄 자체는 저장하지 않는다.
복원 도구는 데이터를 검증하고 파일을 쓰며, 복원한 코드를 자동 실행하지 않는다.

Node가 준비된 환경에서:
  node restoreBundle.mjs "SM_ATLAS_AION_SOURCE.txt" --verify
  node restoreBundle.mjs "SM_ATLAS_AION_SOURCE.txt" --list
  node restoreBundle.mjs "SM_ATLAS_AION_SOURCE.txt" --restore "C:\work\sm-atlas-project-sessions-NEW"

복원 대상은 아직 존재하지 않는 새 폴더여야 한다.
위 예시의 실제 프로젝트는 C:\work\sm-atlas-project-sessions-NEW\sm-atlas-aion 이다.
복원 후 AGENTS.md, CONTRIBUTING.md 및 회사 환경 가이드를 읽고 작업한다.
분할본을 받았다면 SM_ATLAS_AION_PARTS.txt의 번호 순서와 SHA-256을 확인하고,
모든 part TXT를 바이트 그대로 합친 뒤 전체 TXT를 검증·복원한다. 조각을 편집기로 재저장하지 않는다.
